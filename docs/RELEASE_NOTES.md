修复**竖屏视频投到横屏电视被横向拉伸**的问题。

## 问题有多严重

把 720×1280 的竖屏视频投到 1920×1080 的横屏电视，画面会被**横向拉伸 3.36 倍**：

· 测试素材里一个 400×400 的正方形标记被渲染成 1066×317
· 视频内容被铺成 1920×1017（宽高比 1.888），而源是 0.5625

人像会明显发胖、圆形变椭圆。横屏视频（16:9）不受影响，所以只测横屏内容时看不出来。

## 原因

ExoPlayer 直接输出到一块**裸 Surface** 时会把画面**非等比拉伸**去填满它，
而工程里没有任何宽高比约束 —— `SurfaceView` 是 `match_parent`，
两个播放器都没有接 `PlayerView` / `AspectRatioFrameLayout`。

## 修法

把比例交给**布局侧**管：播放器上报画面尺寸，界面据此把 `SurfaceView`
调成视频的形状并居中。

没有去设 `Surface.setVideoScalingMode` —— 那依赖解码器实现，各厂商差异很大
（模拟器的软解就完全没照做）；只要 Surface 的尺寸是对的，无论解码器怎么缩放，
呈现出来的形状都是对的。

## 修复后（同一场景实测）

| 量测项 | 修复前 | 修复后 |
|---|---|---|
| 正方形标记 | 1066×317（宽高比 3.363） | **318×317（1.003）** |
| 视频内容区域 | 1920×1017（宽高比 1.888） | **572×1017（0.5624）** |
| 黑边 | 无（被拉伸填满） | 左右各 674px 对称 |

横屏素材（1280×720）同样正确：正方形 564×565、内容 1808×1017。
DLNA 与 AirPlay 两条通道都通过。

## 另外两处

· 起播后画面会先被拉伸约 1 秒再纠正 —— 解码器要等第一个视频帧解析完才知道
  画面尺寸。现在起播后 3 秒内以 200ms 主动收敛。
· 手机竖着拍的视频常带旋转元数据（横向编码 + rotation=90），这种情况按对调后的
  宽高比处理，否则竖屏内容会被当成横屏摆放。

## 说明

竖屏内容在横屏电视上现在会**居中显示、左右留大片黑边**（1080 高只占 607px 宽）。
这是正确结果 —— 另一种选择是裁掉上下把画面填满，但那会丢内容。
如果你更想要"铺满/裁切"或做成可选项，告诉我。
