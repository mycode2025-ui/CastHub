## 四项功能与入口

| 功能 | 行为与入口 |
|---|---|
| 自动重试 | 设置 → 播放与接管设置。默认开启，网络错误 / HTTP 408、429、5xx 最多重试 3 次，等待 2、4、8 秒。恢复故障时的进度与播放 / 暂停意图。404、403、格式和解码错误直接报错。 |
| 接管规则 | 同一设置入口。直接接管 / 询问后接管 / 播放期间禁止接管；按协议及来源 IP 区分发送设备。同一发送设备可切换自身媒体。询问期间保留旧播放，20 秒不答则拒绝；会话变化后旧批准失效。 |
| 播放队列 | 播放中按 ↑、菜单键，或长按画面 → 播放队列。每行一个地址添加、上一集 / 下一集、播放指定项、上移 / 下移、删除。删除当前项目需确认；仅剩当前项时删除会结束投屏。最多 100 项。 |
| 画面与字幕 | 同一播放菜单 → 画面 / 字幕设置，也可从设置页进入。适应屏幕、填满裁剪、原始大小；字幕字号 50%–200%、离底部 0%–80%、时间偏移 ±10 秒，正值延后、负值提前。 |

队列模式可在队列窗口直接选择单曲、单曲循环、顺序和队列循环。列表仅包含实际收到或手动添加的视频地址，手机未传递的完整播放列表无法推断。队列按协议隔离，结束投屏 / 接管停止原协议 / 服务重启后清空。协议收到的新媒体可加入队列；重复投同一 URL 更新原条目；达到容量时新接收媒体替换最旧非当前条目。

重试预算按每次打开媒体计算，不因短暂恢复而自动刷新，以免弱网反复恢复造成无限重试。手动重试、新媒体、停止或释放会重置 / 取消旧任务。网络库自身的底层请求重试不等同于这 3 次应用恢复；视频 URL 失效后不能凭空刷新授权。直播定位受流自身的可用时间窗口限制。

画面“填满”保持比例并裁剪超出屏幕的部分；原始大小以解码视频像素大小居中，超过屏幕会裁剪。字幕设置作用于 CastHub 内置播放器；独立 AirPlay Server 需要在其自己的界面中配置。设备来源 IP 的区分属于接管策略，不是用户身份认证。

## 复现与证据

Android 14 / API 34 的 `te34` x86_64 AVD；软件 GPU；签名 Release 覆盖安装。媒体来自独立 HTTP Range 服务。新测试使用真实 MP4 中途断开连接，再持续返回 HTTP 503，恢复服务后核对视频进度；持续不可用时确认第 3 次恢复失败后没有继续发起请求。

```powershell
python tools/emulator_144.py
python tools/emulator_regression.py --output dist/validation-1.4.4
python tools/emulator_144_extra.py
```

脚本要求 rooted AVD，8901 提供双音轨 / 字幕媒体，8899 提供标准 MP4。测试脚本会修改并恢复 AVD 上的偏好，拒绝用于真实设备。额外字幕媒体 `timed.mp4` 的第一条字幕正常时间为 4–6 秒，以提前 / 延后后显示时的视频时间和截图核验实际时间轴。

构建记录：`dist/validation-1.4.4/final-build.log`；UI / 故障注入：`acceptance-results.json`、`fault-requests.json`；额外时间轴 / 队列：`extra-results.json`；原有播放回归：`regression-results.json`。截图和协议测试日志均在同目录。
